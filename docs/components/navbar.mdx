# <h1 style={{ fontSize: "3rem" }}>Navbar</h1>

<div style={{ maxWidth: '60%' }}>

A `Navbar` identifica o produto e organiza sua navegação principal. Ela oferece acesso consistente às áreas de primeiro nível sem assumir as ações contextuais de usuário e notificações, tratadas pela [Toolbar](/docs/components/toolbar).

### Quando usar

- Como navegação principal persistente de um produto ou aplicação.
- Para combinar identificação da marca, nome do produto e destinos de primeiro nível.
- Quando os mesmos destinos precisam permanecer previsíveis entre páginas.

### Quando não usar

- Para navegar entre seções locais de uma única página; considere [Tabs](/docs/components/tabs).
- Como barra de ações contextuais; utilize Toolbar.
- Para apresentar uma lista extensa de destinos sem hierarquia.

### Anatomia

1. **Marca:** logotipo completo, reduzido ou slot substituível.
2. **Nome do produto:** identifica a aplicação atual.
3. **Itens de navegação:** destinos principais com rótulos objetivos.
4. **Submenu:** agrupa destinos relacionados quando necessário.
5. **Contexto do cliente:** identifica marca ou ambiente quando aplicável.
6. **Área complementar:** região opcional que deve ser coordenada com a Toolbar para evitar duplicidade.

A anatomia da Navbar e sua relação com a Toolbar serão ilustradas posteriormente.
:::

### Tamanhos e estados

A Navbar possui os tamanhos **Large**, **Medium** e **Small**. Seus itens de submenu contemplam **Default**, **Focus**, **Hover**, **Pressed**, **Selected** e **Select-focused**; o contexto do cliente contempla Default, Hover, Pressed e Focus.

### Comportamento e responsividade

- O destino atual deve permanecer distinguível dos demais.
- Submenus abrem a partir de um controle com estado expandido identificável.
- A variação reduzida pode trocar o logotipo completo pelo curto e condensar rótulos, sem remover o nome acessível.
- Em telas pequenas, priorize produto e acesso à navegação; itens excedentes podem ser agrupados em um menu.
- Navbar e Toolbar não devem apresentar a mesma ação simultaneamente.

## Boas práticas

- Limite a navegação ao primeiro nível mais importante do produto.
- Use rótulos curtos e consistentes com os títulos das páginas de destino.
- Mantenha posição e ordem estáveis entre telas.
- Não use ícones sem nome acessível para representar destinos pouco conhecidos.
- Não esconda o destino atual apenas por uma mudança sutil de cor.

## Referência de variáveis do Figma

Não foram identificadas variáveis exclusivas com prefixo `Ani Navbar`. O componente referencia variáveis compartilhadas de marca, espaçamento e acessibilidade. Elas não constituem uma API CSS pública.

| Variável compartilhada observada | Aplicação |
| --- | --- |
| `spacing/xs` | Espaçamento compacto |
| `spacing/sm` | Espaçamento interno |
| `spacing/xl` | Separação entre regiões |
| `Focus Indicator/Focus Size` | Indicador de foco |
| `border-width/lg` | Espessura do foco |
| `color/brand/01/lightest` | Superfície de marca |
| `color/neutral/light/00` | Conteúdo sobre fundo de marca |

## Acessibilidade

- Use o elemento `nav` ou o landmark `navigation` para agrupar os destinos.
- Quando houver mais de uma região de navegação, forneça nomes acessíveis únicos e objetivos.
- O destino atual deve ser indicado semanticamente, por exemplo com `aria-current="page"`.
- Todos os controles de submenu precisam de nome, estado expandido e foco visível.
- A ordem de foco deve acompanhar a ordem visual e de leitura.
- Consulte o [exemplo oficial de landmark de navegação](https://www.w3.org/WAI/ARIA/apg/patterns/landmarks/examples/navigation.html).
